# D424-Software-Engineering-Capstone
Mobile app soap calculator
Guide for Setting Up and Maintaining the App
The source code for this mobile application is stored in the GitLab repository located at https://gitlab.com/wgu-gitlab-environment/student-repos/SFaust7/d424-software-engineering-capstone.git. All development work should be performed on the Working_Branch rather than the main repository. The published version of the application is reachable through a static download page hosted on GitHub Pages at https://sffaust.github.io/D424-Software-Engineering-Capstone/, which presents a download button for the installable APK file.
Before making changes to the codebase, a developer must install Android Studio Rabbit 1 (version 2026.2.1) along with the Android SDK and JDK. Once these prerequisites are installed, the project is set up by cloning the GitLab repository using the command git clone https://gitlab.com/wgu-gitlab-environment/student-repos/SFaust7/d424-software-engineering-capstone.git and opening the cloned folder as the project directory within the IDE. On first launch, the IDE will prompt for Gradle synchronization and setup, and the project will compile successfully once those dependencies have been resolved.
To begin work on new features or bug fixes, the developer pulls the current state of the project using the command git pull origin Working_Branch. A new feature branch is then created using the command git checkout -b feature_branch, and all modifications are committed to that branch using descriptive commit messages. When the changes have been tested locally and are ready for integration, they are pushed back to GitLab using the command git push origin feature_branch, after which a merge request is opened through the GitLab interface so the work can be reviewed and merged into the Working_Branch.
Releasing an updated version of the application requires two separate actions because the source code and the distribution page live in different locations. First, the developer builds a new signed APK from within Android Studio and uploads that APK to the GitHub repository, so it receives its own downloadable URL. Second, the developer opens the index.html file in the GitHub Pages repository, updates the anchor tag so it points to the newly uploaded APK, and commits the change. After a few minutes, GitHub Pages republishes the site, and users visiting https://sffaust.github.io/D424-Software-Engineering-Capstone/ receive the current build. Maintaining the application therefore involves pulling the latest code from GitLab, creating a feature branch, testing changes locally, merging through a GitLab merge request into Working_Branch, rebuilding the APK, uploading it to GitHub, and updating the download link on the Pages site.
